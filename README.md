## 一、面试流程与题目清单（面经）

### 1. 开场 & 自我介绍（00:00–02:00）
- 简单自我介绍 + 三个项目：在线笔记应用（自研 Markdown 解析器）、B 端权限管理系统（动态路由）、SSE 大模型流式问答平台。

### 2. 项目深挖（02:00–17:30）—— 占比最大，追问很细

**项目一：在线笔记应用（Markdown 解析器 + localStorage）**
- localStorage 是存整个文档还是切片？数据结构怎么设计的？（按 note 数组存）
- 在文档头部/尾部改一个字符，是整页重渲染还是局部渲染？怎么判断渲染哪个模块？（追问到 computed 依赖粒度）
- 简历上写解析性能"1ms 以内"——测试条件是什么？多大的文本量？→ 被当场追问出"简历美化了一下"
- 500ms 防抖自动保存：**连续输入 2~3 分钟没有停顿，内容是不是就丢了？** 怎么兜底？（考察防抖缺陷 + 兜底方案，未答出）
- Markdown 解析是自己实现全部标签还是用现成库？（追问真实性）

**项目二：B 端权限管理系统**
- 权限策略是什么？RBAC 吗？
- 接口有没有做鉴权？（反复追问后确认：只有前端页面权限，接口层没有独立权限点）
- 用户角色信息存在哪里？权限被后台删掉后，停留中的用户还能看到页面吗？（路由守卫 / loaded 标志位问题，未答好）
- 一个页面多个接口对应多个权限点，出现"一个有权限一个没权限"怎么处理？（没听懂，未答）

**项目三：SSE 大模型流式问答平台**
- 为什么选 SSE？做过什么调研？
- SSE vs WebSocket vs 轮询，各自优缺点？✅（答得较好）
- 断线重连在什么情况下发生？怎么实现的？（答得较浅：异常时重试 3 次、间隔 30ms）

**AI 使用情况**（面试官明显很关注）
- 项目里怎么用 AI 的？有什么心得？
- 有没有沉淀 skills / workflow？→ 答了写过一个"知识文档转刷题网页"的 skill 传到 GitHub ✅
- 用没用过 agent loop / harness 这类进阶玩法？→ 只用过 vibe coding，没深入 ❌

### 3. 前端基础（17:30–29:30）
- **盒模型**：IE 传统盒模型 vs 标准盒模型的区别 ✅（基本答对）
- 衍生题：同一个固定宽度的盒子在 IE 和 Chrome 里表现要一致（内容不被挤压），CSS 上怎么做？→ **正解是 box-sizing: border-box，面试官已铺垫盒模型却没接住** ❌
- **三栏布局**：左 100px、右 200px、中间自适应，写一下（grid-template-columns: 100px 1fr 200px / flex 均可）→ 只记得大概，没写出来 ❌
- **localStorage 的 setItem 是同步还是异步？** → 答了"异步"，**错，它是同步的**（这正是前面防抖会卡主线程的原因，前后知识点没串起来）❌
- 浏览器渲染原理：JS 为什么单线程？为什么要异步设计？→ 答得一般
- **事件循环输出题**（同步代码 / setTimeout / Promise.then 混合）：宏任务微任务的宏观思路正确 ✅，但 Promise 内部 then 的嵌套执行顺序判断不出来 ❌

### 4. 手写代码题（29:30–43:30）—— 本场最薄弱环节，连换三题

## 二、面试表现分析

### 突出的地方 ✅

1. **技术选型对比有自己的理解**：SSE / WebSocket / 轮询三者的对比讲得清楚、有条理（单向推送 vs 全双工 vs 重复连接开销），这是全场最流畅的问答。
2. **项目方向选得好，与岗位匹配**：自研 Markdown 解析器、权限系统、SSE 流式 AI 问答——三个项目覆盖面不错，也是面试官愿意花 15 分钟深挖的原因。
3. **诚实**：被追问性能数据时直接承认"简历美化了一下"，没有编造；不会的题都直接说不会。诚实是好品质，但也暴露了简历数据缺支撑的短板。
4. **AI 工具使用有亮点**：写过 skill 并开源到 GitHub，对"用 AI 提升表达/提需求能力"有真实体会，踩中了面试官关注的点。
5. **事件循环宏观框架正确**：同步 → 微任务清空 → 宏任务的执行顺序讲对了。

### 不足的地方 ❌（按严重程度排序）

1. **手写代码全线失守（最大扣分项，占面试后半段 14 分钟）**：并发限制、有序数组合并、深拷贝三题均未写出，导致面试官三次降难度换题。前端实习一面手写题权重很高，这一环节基本决定了面试结果。
2. **基础概念有硬伤**：
   - localStorage setItem 是**同步**的，答成异步——而且这正是自己项目里"写 localStorage 会卡主线程所以要防抖"的原因，前后知识没打通；
   - 盒模型铺垫之后没接住 box-sizing: border-box 这个直接答案；
   - 三栏布局（CSS 最高频手写布局之一）没写出来。
3. **项目经不起边界条件追问**：
   - 性能数据被一问测试条件就露馅，简历上不要写没有测试报告支撑的数字；
   - 防抖自动保存"连续输入就永不保存"的经典缺陷没有兜底方案（正解：防抖 + 节流结合，或 beforeunload / 定时兜底保存）；
   - 权限系统只有前端页面权限、没有接口权限点设计，且对"权限变更后已登录用户如何失效"没有方案。
4. **事件循环细节丢失**：Promise.then 内部嵌套的执行顺序（同步部分 vs 微任务队列）判断不出。
5. **AI 使用停留在 vibe coding**：面试官两次引导 agent loop / harness / workflow，都没有实践经验——在 2026 年的字节前端面试里这是明显的减分项。
6. **反问环节浪费了机会**：把"评价我自己"抛回给面试官，既得不到真实答案，也没有展示对业务/团队/实习内容的兴趣。反问应准备 2~3 个正经问题（如：实习生参与什么业务、团队技术栈、导师带教方式）。

### 综合判断

一面官最后明确说"结果由 HR 同步"且全程主动降难度换题，结合手写题三连挂，**本轮通过概率较低**。但整场暴露的问题非常集中、可修复：不是项目不行，而是**手写代码量严重不足 + 基础细节有硬伤**。

## 三、针对性改进建议

1. **手写题专项（最高优先级）**，每天手写 1~2 题，重点：
   - Promise 并发限制调度器（本场原题，高频必考）
   - 深拷贝（递归 + 循环引用 WeakMap）
   - 防抖/节流（含立即执行版、取消功能）
   - 事件循环输出题（Promise.then 嵌套 10 道以上）
   - 三栏布局 / 水平垂直居中 / 圣杯布局等 CSS 手写
2. **打通知识链**：学到概念要和自己项目挂钩——localStorage 同步阻塞 → 防抖 → 边界兜底，一条链讲到底。
3. **简历数据补支撑**：每个性能数字准备"测试方法 + 数据规模 + 结果"三要素，答不出就删掉。
4. **项目预演"极限三连"**：每个项目自己先问自己三个边界问题（极端场景、失败场景、数据上限），准备好答案再上场。
5. **补 AI 进阶实践**：用 Claude Code / Cursor 等工具实际跑一次 agent workflow（多文件改动、自动测试、review loop），能讲出真实案例。
6. **反问环节预案**：提前准备 2~3 个业务/成长向问题。
